# Contributing to Cryzo

Thanks for helping improve Cryzo.

## Development setup

1. Fork and clone the repository.
2. Install dependencies with `npm install`.
3. Configure a development Convex deployment and the environment variables required for the feature you are working on.
4. Run `npx convex dev` and `npm run dev`.
5. Before opening a pull request, run:

```bash
npm test
npm run typecheck
npm run build
```

## Pull requests

Keep changes focused and describe:

- the user problem being solved;
- the behavior before and after the change;
- how you tested it;
- screenshots for meaningful UI changes;
- any new environment variables, migrations, provider requirements, or billing implications.

For builder/runtime changes, test both a fresh project and an edit to an existing project. For backend changes, verify that the Cryzo Cloud dashboard reflects the actual resources applied. For Marketing changes, verify draft-only behavior separately from explicit publish/schedule actions.

## Generated-app boundaries

Cryzo has two different codebases in play: the Cryzo platform and the apps generated by Cryzo. Keep infrastructure boundaries clear.

- Generated apps must not contain Cryzo platform secrets.
- Generated apps must not invent unpublished Cryzo packages.
- Cryzo Cloud resources are declarative project resources backed by the platform.
- Hosted generated-project execution uses Vercel Sandbox; do not introduce browser WebContainer assumptions into that runtime unless a future architecture change explicitly does so.
- New native mobile projects use Expo + React Native and should share one codebase across iOS and Android.

## Security

Do not put API keys, OAuth secrets, Stripe secrets, store credentials, or customer data in commits, issues, screenshots, fixtures, or pull requests. See [SECURITY.md](SECURITY.md) for private reporting guidance.
